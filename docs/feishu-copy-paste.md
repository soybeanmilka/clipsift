# 用户故事：从飞书复制代码为什么老是报错

## 症状

从飞书文档复制一段代码，粘到编辑器里，看着和原文一模一样，但：

- C++ 编译报 `error: stray '\342' in program`
- Python 报 `IndentationError: unexpected indent`
- TypeScript 报 `SyntaxError: Invalid or unexpected token`
- 命令行报 `command not found`，可命令看着完全正确

重新手打一遍就好了。删掉重贴还是错。用 `Ctrl+Shift+V`（粘贴为纯文本）有时候能好，有时候不能。

## 原因

飞书文档是**富文本**编辑器。你复制时，剪贴板里同时放了好几份数据：

| 格式 | 内容 |
| --- | --- |
| `text/plain` | 纯文本 |
| `text/html` | 带样式的 HTML |
| 私有格式 | 飞书自己的富文本结构 |

问题出在 `text/plain` 这一份里。富文本编辑器为了**保住排版**，会把某些位置的空格换成
"不会自动合并的空格"（`U+00A0` NBSP），把换行换成"不会自动断行的换行"，
还会在段落边界插入零宽字符做标记（`U+200B`）。

这些字符在人眼里就是**普通的空格和空行**，但在编译器眼里是乱码。

`Ctrl+Shift+V` 粘贴纯文本能解决一部分，但它只是"尽量用 text/plain 而不是 text/html"，
**并不会帮你过滤 text/plain 里的隐形字符**。所以有时候还是好不了。

## 为什么是 `\342`

GCC 遇到无法识别的字节时，会把它按**八进制**打出来：

- `U+200B` 的 UTF-8 编码是 `E2 80 8B`
- 首个字节 `0xE2` = 二进制 `1110 0010` = 八进制 `342`
- 所以报 `stray '\342'`

对应的表：

| 报错里的数字 | 十六进制 | 字符 |
| --- | --- | --- |
| `\342` | `0xE2` | `U+200B` 零宽空格（以及大部分 `U+2000` 区段） |
| `\302` | `0xC2` | `U+00A0` 不间断空格 |
| `\343` | `0xE3` | 中文全角标点 |
| `\300` | `0xC0` | 全角空格 `U+3000` |

## 怎么解决

### 手动：先查再删

```bash
clipsift inspect < 你的文件
```

看到 `U+200B` / `U+00A0` 就确认了。

### 一劳永逸：让它在剪贴板里就被洗掉

```bash
clipsift watch
```

挂后台，之后从飞书复制出来的东西**粘之前就已经干净了**，不用记得做任何事。

## 为什么不做成"复制时自动"的浏览器插件

技术上可以，但有几个问题：

1. **只覆盖浏览器**。飞书有桌面客户端、手机端，Word / Excel / PDF 也在浏览器外。
2. **拿不到剪贴板写入权限**。浏览器安全模型不允许网页往剪贴板写任意内容后还修改它。
3. **用户根本不知道要装**。而剪贴板监听是系统级的，一次装上所有来源都覆盖。

剪贴板这一层是**所有复制行为的必经之路**，在这里拦截性价比最高。

## 类似的坑

不止飞书。这些来源都有同样的问题：

- 钉钉文档
- Notion
- 语雀
- 飞书多维表格
- ChatGPT / Claude / 各种 AI 聊天窗口（网页版尤其）
- Word / OneNote
- 从 PDF 里选中的文本
- 网页上的代码块（很多网站的 `<pre>` 里塞了反爬零宽字符）

## 顺带一提

有些网站会故意在代码块里埋零宽字符当**反爬水印**——你复制下来的代码看着对，
但里面每一行都带着你的"指纹"。这种字符正好也被 ClipSift 一起清掉。
